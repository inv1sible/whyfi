# Monitor mission behavior

- **Start** creates one local mission only when none is open. **Stop** saves the final raw snapshot, location data, and capture statistics; the mission remains open. Another **Start** appends to the same mission log and PCAP (subject to the existing 200 MB PCAP limit). PDFs are generated only through **Create PDF** or the explicit **Create PDF and upload** action.
- **Reset** in Nearby closes the open mission and clears favorites and hidden APs. It leaves PDF, log, and PCAP files intact in Missions. The next Start creates a new mission.
- **Continue mission** in Missions copies the selected mission's log, PCAP and capture statistics to a new local UUID, records the source ID in its log, and opens Nearby with all recorded AP/client identities. The edited name is inherited; the new date is appended to the card title and newly generated PDF heading. The source stays intact, including its uploaded marker. An already uploaded mission can be continued this way.
- **Edit** renames a local mission. **Export PCAP** and **Delete mission** are at the top of the card. Active missions require Reset before deletion. **Create PDF**, **Open PDF**, **Export PDF**, and **Refresh PDF** are separate actions: opening a saved PDF does not regenerate it; refresh explicitly regenerates it. File viewing/sharing uses the manifest's restricted `.monitorfiles` provider with read grants and ClipData.
- **Seen again** marks an exact recorded MAC heard in the new capture. **Matches first** sorts these identities ahead of others, then by RSSI. Recorded devices that have not returned stay visible as **Recorded**. Auto/Manual updates also apply to these markers and ordering. Rotating MACs are not linked to a physical device.
- **Show/Hide log** toggles a 160 dp independently scrollable preview of recent events and explains omitted snapshots. **Export full log**, immediately beside that toggle, shares the complete JSONL even when the preview is hidden.
- **All device estimates** includes APs and clients with their own RSSI observations and matching receiver fixes. A client seen only as a downlink recipient has no transmitter RSSI and cannot be located from that downlink. Client estimates describe a potentially moving device's recorded observation area.
- **Replay on Location map** is a separate read-only view. Nearby has no mission picker bar.
- Mission cards are composed lazily. A disposable internal header cache supplies names, dates, file sizes and statuses across app restarts; the authoritative mission directories refresh in the background, with batches on the first uncached load. Tab switches reuse the loaded headers. Header rendering never stats external-storage files or parses logs. Recorded-device details load only when expanded. Replay inventory processing runs off the UI thread and advances incrementally; rewind resets it, and snapshot parsing is shared with location reconciliation. Physical-phone load time remains to be measured.
- While Monitor is visible, Android location warms up before capture (when permission is granted). Without a started/continued/replayed mission, diagnostics show fixes but the map stays empty. The foreground capture service continues to own location recording during a mission.
- Location defaults to all available device estimates. Every displayed estimate includes its own grouped measurement points (up to 80 recent spatial groups), receiver-accuracy circles, estimate uncertainty and illustrative RSSI cones. Cones do not measure antenna bearing or represent a calibrated probability region. Coincident estimate/measurement points cannot define a cone direction. Recorded data remains complete.
- Category chips start unfocused: tap a kind to show only that kind; tap again to restore all kinds. Location's device chips similarly focus/unfocus a favorite. Both left Location actions restore the all-device map. Nearby's existing Matches/Hidden actions clear category focus while keeping their sorting/visibility purpose.
- Hiding a named AP hides every AP with the exact same SSID in the current mission. APs with no SSID are hidden individually by BSSID. The Hidden APs filter restores them. Hiding changes the displayed list; it does not discard recorded evidence.

Acceptance check on a phone: start, stop, start, stop and confirm the mission ID is unchanged and log/PCAP sizes grow without waiting for a PDF. Rename a mission, continue it, and confirm its name and recorded devices are restored with a new ID/date. Capture a known MAC again and test Matches first with Manual/Auto updates. Generate the PDF on request, then upload both missions separately. Test client map selection and one-finger map drag, including while follow-me was enabled. Reset and confirm prior files remain. Hide one of two APs sharing an SSID and confirm both can be restored from Hidden APs.

Regression acceptance on a phone: time Missions on first open and after switching tabs/relaunching; create a PDF, immediately open it, and export PDF/PCAP/full log to another app. Verify the log scrolls inside its short panel. Before starting a mission, check fixes in the information panel without map markers. In live/replay Location, inspect several device estimates together, then focus/unfocus one and inspect measurement accuracy circles and cones. No emulator/device verification is available in the build container.
